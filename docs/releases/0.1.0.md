# Postmodem 0.1.0 — public beta (M2a)

The first version meant to run in public: a staging board people can join and use. It is a
beta: invite-only registration is the recommended mode, and data formats may still change
before 1.0 (migrations will carry boards forward; there is no downgrade).

Image: `ghcr.io/postmodem-bbs/postmodem:0.1.0` (also `:0.1`), signed with cosign.

> **Since the release (2026-11-19):** the project's own staging board is deferred until the
> build is more complete, at the end of M3 at the earliest
> ([M2.md, decision 5](../milestones/M2.md)). Treat 0.1.0 as a preview of what's coming, not
> as a board for real communities yet.

## What's in it

- **Reading** (M1): phpBB2-style index, forums, topics and profiles; phpBB2/Przemo links keep
  working (classic URLs by default, `numbered` and `slug` styles); permissions per forum and
  group; light and dark themes; English and Polish; works without JavaScript; WCAG 2.2 AA.
- **Importing** a phpBB2 / Przemo board from MySQL/MariaDB: users (old passwords keep working),
  groups, forums, permissions, topics, posts with subjects, polls, private messages, watches,
  smilies and avatars (`--files`); a report of everything not imported, by origin.
- **Writing**: new topics, replies, quotes, editing and deleting with phpBB2's rules, preview,
  a BBCode toolbar, signatures.
- **Moderating**: lock, move, split, merge, delete, sticky/announcement, all audited with a
  reason; bans by member, IP and e-mail (wildcards, expiry).
- **Members**: private messages, topic watching with e-mail notifications, search (diacritics
  don't matter), member list, account settings, data export and account deletion.
- **Packages** (on by default, `essentials` profile): quick reply, reports to moderators,
  exact unread tracking.
- **Spam protection**: a self-hosted proof-of-work check on registration, e-mail confirmation,
  invite-only registration, limits for new members, and per-member and per-IP rate limits.
- **Running it**: a web admin panel (settings, forums, groups, permissions with a simulator,
  members, bans, invites, packages, audit log), `postmodem` CLI for the same, backups for SQLite,
  solo (one container, SQLite) or stack (Postgres, Caddy) deployments.

## Deploying

Follow [CONTAINERS.md §4.6](../CONTAINERS.md#46-a-public-staging-board-m2a): real SMTP,
invite-only registration, passwords for (or bans of) the demo accounts before going public,
scheduled backups.

## Upgrade notes

From a pre-release build (M1, `edge` images): start 0.1.0 and let it migrate (migrations
0005–0013 and the packages' own). `POSTMODEM_PROFILE` now defaults to `essentials`; the value
`modern` is gone. The `migrate` role now also applies package migrations: in stack mode, run it
once after upgrading (`docker compose up -d` does).

## Known limitations

- No rich editor, mentions or Markdown yet; no attachments (M3), no polls voting (M2b/M3).
- Changing one's e-mail address isn't possible yet; ask an admin.
- Packages don't add their data to export and deletion yet (reports a member filed stay).
- Search is the database's own full-text index; Meilisearch support comes later.
- Postgres backups use `pg_dump` from the database container, not `postmodem backup`.
- The admin panel covers the basics only (no theme editing, no custom profile fields).
