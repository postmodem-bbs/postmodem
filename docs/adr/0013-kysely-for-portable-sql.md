# ADR 0013 — Kysely instead of Drizzle for the database layer

- Status: accepted · 2026-11-17 · supersedes the "Drizzle ORM" row of DESIGN.md §5.1

## Context
DESIGN.md chose Drizzle for "one schema, two dialects". In practice Drizzle needs a
separate table definition **and** separate query types per dialect (`sqliteTable` vs
`pgTable`, `SQLiteRemoteDatabase` vs `PgDatabase`). M0's one settings table was already
written twice; M1 adds about 17 tables, which would double every repository.

A probe ran one Kysely query module unchanged on `node:sqlite` and on Postgres (PGlite):
inserts with `RETURNING`, explicit legacy ids, Polish text, materialised-path queries
and a whole-subtree path rewrite, all with identical results.

## Decision
- **Kysely** (MIT) is the query builder: one `Schema` type, one implementation of every
  repository port for SQLite and Postgres. `CamelCasePlugin` maps snake_case columns to
  camelCase properties.
- **Engines:** `node:sqlite` through a ~15-line adapter (still no native module in the
  image), postgres.js through `kysely-postgres-js` in production, PGlite through
  `kysely-pglite-dialect` in tests only (`@postmodem/db/testing`).
- **Migrations:** Kysely's migrator with embedded migrations (bundle-safe), lock-protected
  concurrent runs, tables `pm_schema_migrations[_lock]`. The only per-dialect code is the
  generated-id column (`integer … autoincrement` vs `bigint … generated by default as identity`).
- **Portability conventions:** timestamps are epoch milliseconds (`bigint`), flags are
  `0/1` integers, Postgres `int8` is parsed to JS numbers, JSON is read as text and parsed
  in one place.
- **Every repository test runs on SQLite, PGlite and a real Postgres server** (CI service,
  `PM_TEST_PG_URL` locally).

## Things the three-engine suite caught on day one
- Repository calls inside a transaction must use the transaction's connection, or
  single-connection engines (SQLite, PGlite) deadlock.
- Kysely's migrator looks for its tables in **every** Postgres schema unless pinned; it is
  now pinned to `current_schema()`, so two boards in one database under different schemas
  don't see each other's migration state.
- postgres.js re-encodes a parameter it believes is `jsonb`; the value is passed as `text`
  and cast, and read back as `::text` on every driver.

## Consequences
- Drizzle is removed; `drizzle-kit` migration generation is not available. Migrations
  are written with Kysely's schema builder, which is short and reviewable.
- After importing rows with explicit ids, `Database.syncIdSequences()` must be called on
  Postgres (no-op on SQLite).
- The architecture rule keeps `kysely` (and every driver) out of `packages/core`.
