# M1 — Readable board

Status: **plan, approved with decisions below** · 2026-11-17 · builds on M0 ([DESIGN.md §10](../DESIGN.md))

## Goal

At the end of M1 you can **import a real Przemo board and browse it** in
Postmodem, with the old forum structure, users, topics, posts and permissions
intact. Visitors can register and log in, and see exactly what their
permissions allow. Old links (`viewtopic.php?t=123`) keep working, because by
default they *are* the URLs ([ADR 0012](../adr/0012-configurable-permalinks.md)).

Writing (the editor, replying, new topics), the ACP and search are M2. M1 is
deliberately read-mostly: the importer supplies realistic content, so every
read path is built and tested against real-shaped data from day one.

### Demo that defines "done"

1. `postmodem import przemo --from mysql://…` on an anonymised real Przemo
   board (or the generated fixture) finishes, reports what it skipped, and can
   be re-run safely.
2. The board index shows categories, nested forums, topic/post counts and last
   posts; forums and topics paginate; BBCode and smilies render; signatures and
   ranks show.
3. A guest sees only public forums; a logged-in member of a group sees its
   private forum; a moderator sees moderator-only forums. `postmodem perms
   explain` says why.
4. A migrated user logs in with their **old password**, which is upgraded to
   Argon2id on the spot. A new user registers, confirms by e-mail (Mailpit in
   dev) and logs in.
5. With the default `classic` URL style, `https://old-board.example/viewtopic.php?t=123`
   is the topic's own URL. Switching the board to `numbered` or `slug` makes the
   same link 301 to the new canonical URL.
6. All pages pass axe WCAG 2.2 AA in light and dark, work without JavaScript,
   and meet the performance budget on a board with 200k posts.

## Scope

| In M1 | Deferred |
|---|---|
| Domain model + migrations for nodes, topics, posts, users, groups, roles/grants, sessions, audit log | Posting, editor, drafts (M2) |
| Markup pipeline v0: phpBB2 BBCode + smilies → sanitised HTML, cached | Markdown input, mentions (M2) |
| Read UI: index, forum, topic, user profile, who's online (Classic theme) | Memberlist, search (M2) |
| Auth: register, verify e-mail, log in/out, password reset, sessions, legacy hash upgrade | Passkeys, TOTP, OIDC (M2+) |
| Permissions engine: capabilities, roles, scoped grants, reason chains, batched checks, visibility states | Permission simulator UI, ACP (M2) |
| Mail: `log://` and `smtp://` transports, job queue v0 for sending | Digests, notifications (M2) |
| Importer: vanilla phpBB2 + Przemo hierarchy, from a live MySQL/MariaDB | Importer slices for Przemo packages (M3, with each package) |
| Configurable permalinks: `classic` (default), `numbered`, `slug` | Custom token patterns |
| CLI admin basics: `init`, `user`, `group`, `forum`, `perms explain` | Web ACP (M2) |

Importing the vanilla phpBB2 subset of a Przemo board covers about 80% of what
people actually read: forums, topics, posts, users, groups, ranks, smilies and
permissions. Przemo's extra tables (attachments, post history, warnings…)
are reported as "not imported yet" and land with their packages in M3
(PACKAGES.md §3, EP-12).

## Slices

Each slice is a vertical, demoable increment with its own tests. Order
matters where noted; slices 2, 4 and 5 can run in parallel once slice 1 is in.

### Slice 1 — Domain model & migrations *(done 2026-11-17)*

> Built with Kysely instead of Drizzle ([ADR 0013](../adr/0013-kysely-for-portable-sql.md)):
> domain types, repository ports and pure tree/name/slug logic in `packages/core`; one
> repository implementation in `packages/db`, tested on SQLite, PGlite and real Postgres 18.
> Counters are recomputed with `recount()`; incremental updates come with posting (M2).
> Users are unique per (origin, normalised name); e-mails case-insensitively.

Tables (both dialects, expand-only migrations):

| Table | Key points |
|---|---|
| `nodes` | id, parent_id, materialised `path`, `kind` (category / forum / link), position, title, description, slug, counts (`topics`, `posts`), `last_post_id`, `visibility_state` |
| `topics` | id, node_id, title, slug, author_id, `type` (registered topic types: normal / sticky / announcement; global announcement is a module per ADR 0004), `locked`, `moved_to`, counts, first/last post ids, `visibility_state`, created/updated |
| `posts` | id, topic_id, author_id (may be remote, ADR 0009), `source`, `format` (`bbcode-phpbb2`, later `markdown`, `html-remote`), `rendered`, `render_version`, `visibility_state`, created/edited, edit count |
| `users` | id, username, `username_key` (normalised for uniqueness), email, `origin` (`local` / remote host), created, last_seen, post_count, rank, signature (source + format), avatar ref, locale, timezone |
| `credentials` | user_id, kind (`password`), `hash`, `scheme` (`argon2id` / `phpbb2-md5`), updated. Separate table, so remote users never have one |
| `email_tokens` | verification and reset tokens (hashed), expiry |
| `sessions` | id (hashed), user_id, created, last_seen, expires, user agent class (no raw IP by default) |
| `groups`, `memberships` | phpBB2 group types (open / closed / hidden), group moderators |
| `roles`, `role_capabilities`, `grants` | grant = (role, group or user, scope node or global, effect). DESIGN §5.3 |
| `ranks`, `smilies` | vanilla phpBB2 features (core) |
| `audit_log` | actor, action, target, reason, at (core per PACKAGES §0.2) |
| `legacy_ids` | (source, kind, legacy_id) → new id, for re-runs and for content whose number was taken |
| `slug_history` | (kind, slug) → id, so renamed topics/forums keep resolving in `slug` style |

**IDs:** internal 64-bit integers. Imported content **keeps its legacy
number**, so `classic` URLs are unchanged after migration. Public URL shape is a
board setting ([ADR 0012](../adr/0012-configurable-permalinks.md)); `slug_history`
keeps renamed slugs redirecting.

Tests: migrations on SQLite + Postgres (existing harness), repository tests,
materialised-path moves.

### Slice 2 — Markup pipeline v0

- Parser for the **phpBB2 BBCode dialect**: strips the per-post `bbcode_uid`
  suffixes (`[b:1a2b3c4d5e]`); handles `b i u quote quote="name" code list
  list=1 list=a * url url= img email color size`; malformed nesting degrades
  to text, as phpBB2 did.
- Smilies by code, from the `smilies` table.
- AST → HTML through a strict allow-list sanitiser; links get `rel="ugc nofollow noopener"`;
  images become lazy-loaded with no referrer.
- Output cached in `posts.rendered` with `render_version`; bumping the version
  re-renders lazily on read and in a background job.
- **Outside contexts** (EXTENSION-POINTS §7.2): `plainText` and `excerpt`
  renderers for titles, meta descriptions and later feeds.
- Golden tests from real phpBB2 output: render legacy posts, compare structure.
- Fuzzing: random BBCode never produces unsanitised HTML.

### Slice 3 — Read UI (Classic theme) *(after 1, uses 2 and 5)*

| Page | Contents |
|---|---|
| Board index | categories → forums (nested, Przemo "packing" levels as a theme option), topic/post counts, last post, who's online (from sessions), newest member |
| Forum | sub-forums, stickies/announcements first, paginated topics with replies/views/last post, locked/moved markers |
| Topic | paginated posts, author card (rank, post count, joined, avatar), signature, permalink per post, first-unread placeholder |
| Profile | public profile fields, post count, recent topics (permission-filtered) |
| Errors | 403 vs 404 that doesn't leak whether a private forum exists |

- Accessible pagination (`nav` + `aria-current`), breadcrumbs, `rel=next/prev`,
  one `h1` per page, real tables only where they're tabular.
- Meta and JSON-LD `DiscussionForumPosting` for public topics.
- Topic view counts through the Counters service (minimal in-memory → batched flush),
  the first real user of PACKAGES §1 "Counters".
- E2E + axe on every page; no-JS test for navigating and logging in.

### Slice 4 — Auth & sessions

- Registration: username rules (length, allowed characters, Unicode
  normalisation + confusable check, disallowed names), e-mail, password
  (length ≥ 10, no composition rules, optional breached-password check off by
  default), board rules acceptance stored with a version.
- E-mail verification and password reset via single-use hashed tokens.
- Login with username or e-mail; **legacy `phpbb2-md5` hashes verified once,
  then replaced with Argon2id** (Node 24's built-in `crypto.argon2`, no native
  module; OWASP baseline m=19 MiB, t=2, p=1 took 15 ms in testing).
- Sessions: server-side, `__Host-` cookie, `HttpOnly`, `SameSite=Lax`, rotated
  on login, idle and absolute expiry, "log out everywhere".
- Throttling: per account and per IP (in-memory solo / DB stack), with
  progressive delays rather than lockouts. Full lockout policy is the
  `login-security` module (M3).
- Mail: `POSTMODEM_MAIL_URL` with `log://` and `smtp://`; sending goes through
  a DB-backed job queue v0 run by the `worker` role (the first real job).
- `postmodem init` creates the first admin non-interactively from env
  (`POSTMODEM_ADMIN_EMAIL`, `POSTMODEM_ADMIN_PASSWORD_FILE`).

### Slice 5 — Permissions engine

- Capability registry with core capabilities: `node.view`, `node.read`,
  `topic.create`, `topic.reply`, `post.edit.own`, `post.delete.own`,
  `topic.sticky`, `topic.announce`, `poll.vote`, `poll.create`,
  `moderate.*`, `admin.*`.
- Built-in roles mirroring phpBB2's levels: Guest, Registered, Private
  member, Moderator, Admin; importer maps `auth_*` columns (`ALL / REG / ACL /
  MOD / ADMIN`) and `auth_access` rows onto them.
- Resolution: **never > deny > allow > unset**, nearest scope wins; **reason
  chain** on every decision (EXTENSION-POINTS §4).
- `checkMany` for listings (one query per page, not per row), cached per
  request and invalidated on grant changes.
- Visibility states `core:public` / `core:deleted`, with counts using the
  `counts` flag (EXTENSION-POINTS §2.1).
- `postmodem perms explain --user alice --node 7 --capability node.read`.
- Property tests: random grant sets checked against a naive reference implementation.

### Slice 6 — Importer *(can start with slice 1; finishes after 4 and 5)*

- Source: a running MySQL/MariaDB with the Przemo database (pure-JS `mysql2`
  driver). Dev profile `legacy` adds MariaDB 10.x to the dev stack.
- **Status:** the fixture generator and images exist (`tools/fixtures`, built
  ahead of M1 on 2026-11-17): `small` ≈ 4.3k posts, `large` ≈ 209k posts, with
  a manifest of every planted quirk. The importer work starts from them.
- **Fixture only (decided: no real board database is available):** load
  Przemo's own `mysql_schema.sql` + `mysql_basic.sql` into MariaDB, then a
  generator fills it with deterministic fake content (Polish and English text,
  all BBCode tags, nested categories, private forums, groups, 200k posts for
  the performance test). No real personal data in the repo.
- Because there's no real data, the generator also **deliberately produces the
  known real-world mess**: cp1250 bytes in latin2 columns, double-encoded UTF-8,
  HTML entities stored by old phpBB versions, broken BBCode nesting, orphaned
  posts and topics, users deleted with posts left behind, `bbcode_uid`
  mismatches, smilies whose images are missing.
- `postmodem import przemo --report-bundle` writes an **anonymised** diagnostics
  file (structure, counts, anomaly samples with text replaced by length/charset
  fingerprints) that admins can attach to a bug report, so real-world quirks
  surface after release without anyone sharing their database.
- Converts **latin2 → UTF-8** (the Przemo schema uses `latin2_general_ci`),
  HTML entities, `bbcode_uid` stripping, smilies, unsalted MD5 hashes (kept as
  `phpbb2-md5` until first login).
- Maps categories + Przemo sub-forums (`cat_main`) into the node tree,
  `auth_*` and `auth_access` to grants, groups and memberships, ranks.
- Idempotent and resumable (checkpoint per table and batch); `--dry-run`.
- Final report: counts per entity, plus **every legacy table, column and
  config key not read**, checked against Przemo's uninstaller list (PACKAGES §0).
- Runs as `postmodem import przemo` in the container, so admins never install
  anything else.

### Slice 7 — Permalinks & finishing

- `urls` service + SvelteKit `reroute`: all three styles resolve; non-canonical
  requests 301 to the current style; `start=` ↔ `page=` conversion; `#p<id>` post
  anchors; slug generation with Polish transliteration and `slug_history`.
- Classic covers `viewtopic.php?t=…|p=…`, `viewforum.php?f=…`, `index.php?c=…`,
  `profile.php?mode=viewprofile&u=…` exactly as phpBB2 did.
- E2E: the same topic reached through all three styles in all three settings.
- Performance pass on the 200k-post fixture: index, forum page 1 and last,
  topic page 1 and last, p95 < 150 ms on 1 vCPU (DESIGN §5.1); add indexes as
  the measurements require.
- Docs: importer guide, upgrade notes, updated CONTAINERS/DESIGN.

## Definition of done

- The six demo points above, in CI on both SQLite and Postgres.
- Every page: e2e test, axe clean (light/dark/forced-dark), works without JS,
  Polish and English complete.
- Importer run on the fixture in CI (MariaDB service container), with a
  snapshot of the report.
- No new native modules in the image; image still under the size budget.
- ADRs for any decision that deviates from DESIGN.

## Risks

| Risk | Mitigation |
|---|---|
| BBCode edge cases in real boards (broken nesting, phpBB2 quirks), with no real board to test against | Golden tests from phpBB2's own bbcode.php behaviour; a generator that reproduces known quirks; degrade to text, never to raw HTML; per-post render errors logged, not fatal; anonymised report bundles from early adopters |
| Charset chaos (latin2 declared, cp1250 or UTF-8 actually stored, double-encoding) | Detect per column on a sample; importer flag to force a charset; report suspicious rows |
| Performance of the materialised-path tree and counts on SQLite | Denormalised counters updated in the same transaction; measure on the 200k fixture early (slice 3, not slice 7) |
| Permission checks on listings becoming N+1 | `checkMany` from the start; e2e query-count assertions |
| Unsalted MD5 hashes in the database until users log in | After the import, the ACP/CLI can force a reset for accounts that haven't logged in for N months; the hashes are never shown anywhere |

## Decisions (2026-11-17)

1. **Real data:** none available; the importer is validated against a generated
   fixture that reproduces known real-world quirks, plus anonymised report
   bundles from early adopters after release.
2. **URL shape:** configurable like WordPress permalinks, **phpBB2-classic by
   default** ([ADR 0012](../adr/0012-configurable-permalinks.md)).
3. **Posting:** M1 stays read-only; the full editor arrives in M2.
